# 信息安全管理制度

## 第一章 总则

### 第一条 制定目的

为保护公司信息系统、数据、账号、设备和业务资料的安全，防范数据泄露、账号滥用、恶意软件、网络攻击及其他信息安全风险，制定本制度。

### 第二条 适用范围

本制度适用于：

1. 公司全体正式员工；
2. 试用期员工；
3. 实习生；
4. 劳务派遣人员；
5. 外包和合作人员；
6. 经授权访问公司系统、网络或数据的其他人员。

### 第三条 基本原则

信息安全管理遵循以下原则：

1. 最小权限；
2. 按需访问；
3. 数据不出域；
4. 账号实名使用；
5. 重要操作可追溯；
6. 敏感信息受控；
7. 安全事件及时报告；
8. 谁使用、谁负责。

任何人员不得以工作便利为由绕过公司安全控制。

## 第二章 信息和数据分级

### 第四条 数据分级

公司信息和数据分为四个等级：

| 数据等级 | 名称 | 示例 |
|---|---|---|
| L1 | 公开数据 | 已正式发布的官网信息、公开宣传材料 |
| L2 | 内部数据 | 内部通知、普通流程文件、一般工作资料 |
| L3 | 敏感数据 | 客户信息、员工信息、合同、财务数据、业务明细 |
| L4 | 核心数据 | 密钥、核心系统配置、重大经营数据、高敏感客户数据 |

数据等级越高，访问、传输、保存和外发限制越严格。

### 第五条 公开数据

L1公开数据可以在公司授权的公开渠道使用。

信息尚未正式发布前，不得仅因未来计划公开而按照公开数据处理。

### 第六条 内部数据

L2内部数据原则上只能在公司内部使用。

未经授权，不得：

1. 发送至个人邮箱；
2. 上传到个人网盘；
3. 发布到公开网站；
4. 发送给无业务关系的外部人员；
5. 通过未经批准的即时通信工具传输。

### 第七条 敏感数据

L3敏感数据包括但不限于：

1. 客户姓名、电话号码、证件号码；
2. 客户账户和交易信息；
3. 员工个人信息；
4. 工资和绩效信息；
5. 合同及供应商报价；
6. 未公开财务数据；
7. 业务经营明细；
8. 系统日志中包含的用户信息；
9. 医疗、身份或家庭等敏感个人信息；
10. 公司认定的其他敏感数据。

处理L3敏感数据应当符合授权范围，并采取脱敏、加密或访问控制措施。

### 第八条 核心数据

L4核心数据包括但不限于：

1. 系统管理员密码；
2. API密钥；
3. 数据库密码；
4. 加密私钥；
5. 生产系统核心配置；
6. 未经脱敏的高敏感客户数据；
7. 重大决策和重大交易信息；
8. 安全防护策略的敏感细节。

L4核心数据仅限经过专门授权的人员访问。

任何人员不得在聊天、邮件、工单、源代码或普通文档中以明文保存L4核心数据。

## 第三章 账号与身份认证

### 第九条 账号实名使用

公司账号应当由本人使用。

禁止：

1. 将账号借给他人；
2. 使用他人账号；
3. 多人共用实名账号；
4. 使用离职人员账号；
5. 使用无法识别责任人的公共账号。

确需使用系统服务账号的，应当履行专项审批并明确责任人。

### 第十条 密码要求

公司账号密码应当满足系统规定的复杂度要求。

用户不得：

1. 使用容易猜测的密码；
2. 在多个重要系统中使用相同密码；
3. 将密码写在公开可见位置；
4. 通过即时通信工具明文发送密码；
5. 将密码提交到代码仓库；
6. 向任何人员透露一次性验证码。

怀疑密码泄露时，应当立即修改密码并报告。

### 第十一条 多因素认证

支持多因素认证的重要系统，应当按照公司要求启用多因素认证。

用户不得关闭、绕过或转交多因素认证设备。

### 第十二条 权限申请

用户申请系统权限时，应当说明：

1. 申请人；
2. 所属部门；
3. 申请系统；
4. 所需角色或权限；
5. 业务用途；
6. 使用期限；
7. 数据范围；
8. 审批人。

权限应当以完成工作所必需的最小范围为限。

### 第十三条 权限审批

普通业务系统权限原则上由以下人员审批：

1. 直属经理；
2. 系统负责人。

涉及L3敏感数据的权限，还应当由数据负责人或信息安全人员审核。

涉及L4核心数据、生产管理员权限或批量导出权限的，还应当由信息技术负责人和信息安全负责人审批。

### 第十四条 权限复核

系统负责人应当定期复核用户权限。

存在下列情况之一时，应当及时调整或回收权限：

1. 员工离职；
2. 员工转岗；
3. 项目结束；
4. 临时权限到期；
5. 长期未使用；
6. 发现权限超出工作需要；
7. 账号存在安全风险。

### 第十五条 离职和转岗权限处理

员工离职时，相关账号和权限原则上应当不晚于离职生效时间关闭或回收。

员工转岗后，原岗位不再需要的权限应当及时取消，不得只增加新权限而保留全部旧权限。

## 第四章 终端和办公设备安全

### 第十六条 公司设备使用

公司提供的计算机、手机、移动存储设备及其他终端应当用于授权的工作用途。

未经批准不得：

1. 擅自拆卸设备；
2. 关闭安全防护软件；
3. 安装盗版或来源不明的软件；
4. 修改安全配置；
5. 将设备长期交给他人使用；
6. 使用设备从事违法或明显高风险活动。

### 第十七条 软件安装

员工原则上只能安装公司批准的软件。

确因工作需要安装新软件的，应当通过规定流程申请。

存在下列情况的软件不得安装：

1. 来源不明；
2. 包含恶意代码风险；
3. 违反软件许可；
4. 具有未授权远程控制能力；
5. 可能绕过公司网络或数据控制；
6. 信息安全部认定为高风险。

### 第十八条 移动存储设备

使用U盘、移动硬盘等移动存储设备处理公司数据时，应当符合公司安全要求。

L3及以上数据原则上不得存储在未加密的移动存储设备中。

未经批准不得使用个人移动存储设备复制公司敏感数据。

### 第十九条 屏幕和办公环境

员工离开工位时应当锁定屏幕。

打印或展示敏感信息时，应当避免无关人员查看。

包含敏感信息的纸质材料不再使用时，应当通过符合要求的方式销毁，不得直接丢入普通垃圾桶。

## 第五章 邮件、即时通信与文件传输

### 第二十条 工作邮箱使用

公司工作信息原则上应当使用公司邮箱或其他经批准的系统传输。

不得使用个人邮箱发送：

1. 客户信息；
2. 员工敏感信息；
3. 合同和报价材料；
4. 未公开财务数据；
5. 系统配置；
6. L3或L4数据；
7. 公司规定不得外发的其他资料。

### 第二十一条 外发审批

向公司外部发送L2内部数据时，应当确认接收方具有业务必要性。

向外部发送L3敏感数据时，应当至少取得：

1. 直属经理批准；
2. 数据负责人批准；
3. 必要时的信息安全审核。

L4核心数据原则上不得对外发送。确有必要的，应当履行专项审批，并使用公司认可的加密和传输方式。

### 第二十二条 文件外发要求

外发文件前应当检查：

1. 接收方是否正确；
2. 是否包含无关数据；
3. 是否需要脱敏；
4. 是否需要加密；
5. 是否设置有效期；
6. 是否限制转发和下载；
7. 是否记录审批信息。

因误选收件人造成的文件误发，也属于信息安全事件。

### 第二十三条 即时通信工具

员工不得通过未经批准的个人即时通信账号传输L3或L4数据。

工作群中不得发送：

1. 系统密码；
2. API密钥；
3. 完整身份证号码；
4. 完整银行卡号；
5. 未脱敏客户清单；
6. 生产数据库连接信息；
7. 其他核心或高敏感信息。

## 第六章 大模型和外部智能工具使用

### 第二十四条 公共大模型使用原则

员工使用公共大模型、在线翻译、在线代码分析或其他外部智能工具时，不得输入公司L3或L4数据。

不得输入的内容包括：

1. 未脱敏客户信息；
2. 员工敏感个人信息；
3. 未公开经营数据；
4. 供应商保密报价；
5. 合同保密条款；
6. 生产环境日志；
7. 源代码中的密钥；
8. 数据库结构和真实数据样本；
9. 内部账号密码；
10. 其他受限信息。

### 第二十五条 允许使用的数据

使用公司批准的外部智能工具时，可以处理：

1. 已公开的L1信息；
2. 不包含内部业务信息的通用问题；
3. 经过批准和充分脱敏的样例数据；
4. 不含公司机密的通用代码示例；
5. 公司明确允许使用的其他内容。

即使信息已经脱敏，仍应当检查是否能够通过组合字段重新识别个人或业务主体。

### 第二十六条 公司内部大模型

公司内部部署并经过安全评估的大模型，可以按照其授权范围处理内部数据。

内部大模型并不代表所有数据均可无限制输入。

用户仍应遵循：

1. 数据分级；
2. 最小必要；
3. 访问权限；
4. 用途限制；
5. 日志和审计要求；
6. 特定业务系统的补充规则。

### 第二十七条 大模型生成内容使用

大模型生成的内容应当由使用人员进行核验。

不得未经检查直接将大模型生成的以下内容用于生产：

1. 法律结论；
2. 财务数据；
3. 客户决策；
4. 生产代码；
5. 系统配置；
6. 审批结果；
7. 重要对外材料。

大模型不得替代必须由授权人员作出的审批和最终决策。

## 第七章 开发和代码安全

### 第二十八条 密钥管理

开发人员不得将以下内容提交到Git或其他代码仓库：

1. API密钥；
2. 数据库密码；
3. 私钥；
4. 访问令牌；
5. 云服务凭证；
6. 生产系统账号密码；
7. 其他认证信息。

密钥应当通过环境变量、密钥管理服务或公司批准的安全方式保存。

### 第二十九条 测试数据

开发和测试环境原则上不得直接使用未经脱敏的生产数据。

需要使用生产数据特征进行测试时，应当：

1. 获得批准；
2. 删除直接身份标识；
3. 对敏感字段脱敏；
4. 限制数据量；
5. 限制访问人员；
6. 在使用结束后及时删除。

### 第三十条 代码审查

涉及以下内容的代码变更应当进行代码审查：

1. 身份认证；
2. 权限控制；
3. 数据加密；
4. 文件上传；
5. 外部接口调用；
6. 支付和审批；
7. 日志记录；
8. 敏感数据处理。

代码审查不能替代安全测试。

### 第三十一条 日志安全

系统日志应当满足问题排查和审计需要，但不得无必要地记录完整敏感信息。

日志中应当避免记录：

1. 密码；
2. API密钥；
3. 访问令牌；
4. 完整身份证号码；
5. 完整银行卡号；
6. 完整医疗信息；
7. 未脱敏客户数据；
8. 请求中的其他高敏感字段。

必要时应当采用掩码、哈希或脱敏后的值。

## 第八章 网络和远程访问安全

### 第三十二条 公司网络

接入公司网络的设备应当符合安全要求。

未经批准不得：

1. 私自搭建无线热点；
2. 将公司网络共享给无关人员；
3. 扫描或攻击公司系统；
4. 绕过代理、防火墙或访问控制；
5. 接入存在明显安全风险的设备。

### 第三十三条 远程访问

远程访问公司系统应当使用公司批准的VPN、零信任或其他安全接入方式。

不得将远程访问账号提供给他人使用。

在公共场所远程办公时，应当避免：

1. 屏幕内容被他人查看；
2. 使用不可信公共网络；
3. 在无人看管时保持系统登录；
4. 将敏感文件保存在公共设备中。

## 第九章 第三方和供应商安全

### 第三十四条 第三方访问

供应商、外包人员或其他第三方访问公司系统和数据前，应当：

1. 明确业务必要性；
2. 签署保密协议；
3. 完成相应审批；
4. 使用独立实名账号；
5. 限定权限范围；
6. 限定访问期限；
7. 保留访问日志；
8. 项目结束后及时回收权限。

### 第三十五条 第三方数据提供

向第三方提供数据时，应当检查：

1. 合同是否允许；
2. 是否取得必要授权；
3. 是否符合数据最小化；
4. 是否需要脱敏；
5. 是否采用安全传输；
6. 第三方是否具备保护能力；
7. 是否需要设置删除期限。

第三方不得擅自将公司数据用于合同约定之外的用途。

## 第十章 安全事件管理

### 第三十六条 安全事件类型

以下情况可能构成信息安全事件：

1. 账号或密码泄露；
2. 文件误发；
3. 设备丢失；
4. 病毒或勒索软件感染；
5. 未授权访问；
6. 数据被异常下载或复制；
7. 敏感信息上传到公共平台；
8. 系统遭受攻击；
9. 安全配置被擅自关闭；
10. 其他可能影响信息安全的异常情况。

### 第三十七条 安全事件上报时限

发现信息安全事件或疑似事件后，应当立即采取必要措施，并原则上在三十分钟内向信息技术部或信息安全部报告。

不得因为以下原因延迟报告：

1. 尚未确认是否造成损失；
2. 担心承担责任；
3. 希望自行解决；
4. 事件发生在非工作时间；
5. 认为影响范围较小。

### 第三十八条 上报内容

安全事件报告应当尽量包括：

1. 发现时间；
2. 事件发生时间；
3. 涉及系统或设备；
4. 涉及数据类型；
5. 已知影响范围；
6. 已采取的措施；
7. 当前联系人；
8. 相关截图或日志。

不得为了收集完整信息而延迟首次报告。

### 第三十九条 初步处置

在保证安全且具备相应能力的情况下，发现人员可以采取：

1. 修改泄露密码；
2. 断开受感染设备网络；
3. 撤回误发邮件；
4. 停止继续上传或传输；
5. 保存必要证据；
6. 联系接收方删除误发文件；
7. 按照安全人员指示采取其他措施。

未经授权不得擅自删除可能用于调查的重要日志或证据。

## 第十一章 违规处理

### 第四十条 一般违规

违反本制度但尚未造成严重影响的，公司可以要求：

1. 立即整改；
2. 完成安全培训；
3. 修改密码；
4. 删除违规保存的数据；
5. 暂停相关权限；
6. 提交书面说明。

### 第四十一条 严重违规

存在以下行为之一的，可以认定为严重违规：

1. 故意泄露公司敏感数据；
2. 买卖或非法提供客户信息；
3. 故意共享高权限账号；
4. 将核心密钥公开到代码仓库；
5. 隐瞒重大安全事件；
6. 伪造审批或安全记录；
7. 绕过安全控制造成重大损失；
8. 其他严重危害公司信息安全的行为。

公司可以根据情节采取纪律处分、追究损失或移交有关部门处理。

## 第十二章 信息权限和审计

### 第四十二条 制度查询权限

所有员工可以查询本制度中的一般安全要求。

以下内容仅限信息安全、信息技术管理人员及经授权人员查看：

1. 具体安全设备配置；
2. 核心系统防护策略；
3. 漏洞技术细节；
4. 管理员账号信息；
5. 密钥保存位置；
6. 应急处置中的高敏感技术信息。

### 第四十三条 操作审计

涉及以下操作的系统应当保留审计记录：

1. 登录和退出；
2. 权限申请和变更；
3. 敏感数据查询；
4. 数据导出；
5. 文件外发；
6. 管理员操作；
7. 密钥访问；
8. 安全事件处理；
9. 其他重要操作。

审计记录应当包含必要的用户、时间、对象、结果和请求标识。

## 第十三章 附则

### 第四十四条 制度解释

本制度由信息安全部负责解释，信息技术部协助执行。

### 第四十五条 生效日期

本制度版本号为V1.0，自2026年1月1日起生效。

新版本制度生效后，与新版本不一致的旧规定停止执行。

### 第四十六条 历史版本适用

查询历史安全事件或历史权限操作时，应当使用事件发生日期或操作发生日期当时有效的制度版本。

不得直接使用当前最新制度判断历史行为是否符合当时的规定。
