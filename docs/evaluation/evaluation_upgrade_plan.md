## Work breakdown and validation sequence

1. E2: schema validation -> fixture ownership/isolation -> multi-turn runner -> deterministic tool/state assertions -> negative safety cases -> SQLite/PostgreSQL integration -> reports. Reuse `recall_at_k`, `reciprocal_rank`, `ndcg_at_k`; add no duplicate ranking math.
2. E3: rubric/evidence schema -> offline malformed/error fixtures -> budgeted provider -> human-blind calibration intake -> agreement report. Keep approval amount, permission, idempotency and DB state outside Judge authority.
3. E4: common experiment manifest -> blinded scoring -> swapped runs -> safety exclusion -> statistics and saved reproducibility seed. Unknowns remain explicit.
4. E5: provenance-preserving bad-case export -> human review -> approved regression intake -> existing CI extension. Measure non-safety baselines before setting thresholds. Keep safety violations zero-tolerance.

Langfuse dataset/experiment/scores integration belongs after local result contracts stabilize. Use the pinned SDK's supported APIs and confirm target server compatibility again at implementation time. Keep raw employee and policy data local; only approved synthetic fixtures may be uploaded under explicit scope. Every experiment manifest must distinguish Offline Mock, Deterministic Integration, Live LLM, Human-reviewed and Production evidence.

E1 alone adds optional privacy-preserving tracing, async correlation, failure isolation and reproducible regression evidence. It does not add a calibrated Judge, certified independent benchmark, production success rate or generalized E2E task-success scorer. Resume wording must preserve that boundary.
